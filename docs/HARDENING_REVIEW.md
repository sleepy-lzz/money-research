# v0.1.1 Data Correctness / Point-in-Time Hardening

复核日期：2026-09-10。结论基于当前代码和离线反例测试，不以外部 review 为事实依据。本版不增加因子、AI 选股或真实交易。

**当前不能声称真实 Tushare 回测已经做到绝对 PIT、无幸存者偏差、无虚假成交。** 本版修正了可复现的软件错误，并增加证据门禁。正常下载今天能拿到的历史数据仍属于历史重建；没有独立历史档案时，真实快照 `tradable=false`，置信度为 `unverified_reconstruction`。通过证据校验也只标为 `receipt_bound_source_attestation`，仍需外部来源审计。

## 最重要的四个问题

### 停牌日

`hardening.make_spine` 先按支持范围内证券的上市区间与交易日历构造 session，再合并行情。缺行情与明确停牌是不同状态：

* 有独立的全天停牌证据：`suspended=true`、`tradeable=false`，OHLC 保留空值。
* 只有缺行情，没有全天停牌证据：状态未知，阻止正式模拟。`suspend_d` 的 S/R 事件本身不自动证明全天停牌。
* 有持仓时可用单独的 `valuation_price/valuation_date/valuation_kind` 表示上次实际收盘的陈旧估值；它不能作为成交价。跨除权日而没有可信新价格时停止估值，不能把旧价直接平移。

这同时修复了停牌日被删掉后，20 日平均成交额被抬高的问题。动量窗口仍使用有效行情观测数，这属于明确保留的策略定义。

### 退市与历史 universe

`stock_basic` 分别请求 L/D/P，显式索取上市、退市日期并分页。任何状态请求失败、分页不前进或退市日期缺失都不能被其他成功请求掩盖。历史集合按 `list_date <= D < delist_date` 构建，策略和执行共用沪深 MAIN eligibility。

但 L/D/P 全部返回成功也不等于历史集合完备。因此还要求每个历史交易日独立的完整 inventory receipt，与标准化集合逐项匹配。删除证券并同步删除它的行情，仍会与独立 inventory receipt 冲突。

这里的“独立”是数据来源要求，不能靠给当前表自己生成一个 JSON 实现。哈希能证明内容没变，不能证明供应商没漏数据，也不能证明人工填写的时间真实。当前没有真实档案验收，不能宣称已消除所有幸存者偏差。持仓在退市后缺少结算/估值依据时明确停止，不自动清零或假设最后价格卖出。

### available_at 的证明

保留业务日、`published_at`、`fetched_at`、`available_at`。在线 ingestion 用本机当前时间记录实际获取时间，不提供回填历史获取时间的参数。receipt 要求带时区、`published_at <= available_at`、`fetched_at <= available_at <= decision_cutoff`。

真实快照需要逐日 session receipt，绑定行情、基准、当日 universe、已知公司行动和下一交易日，预热期也在检查范围内。引擎还按实际决策时刻复核，避免同日 22:00 的修订进入 19:00 决策。今天下载的历史数据不能只凭旧 `trade_date` 获得历史可见性。

历史 receipt 的导入路径是兼容既有可信档案，不是授予回填时间的许可。它仍需要来源保管链、原始记录和采集时钟审计。当前不是经过认证的档案服务，也未接入完整财报修订流。

### AI 接新闻后怎样防未来泄漏

证据在 ingestion 层生成/核对 `evidence_id/url/published_at/fetched_at/available_at/content_hash/content`，先按精确截止时间过滤，再传给 provider。缺时间、无时区、内容哈希错误或晚到的证据不能进入历史研究；没有有效证据就不调用 provider。

provider 得到副本，输出只能引用已通过校验的证据，不能改 URL、内容或时间。缓存键包含截止时刻和证据内容版本。历史 backtest/replay 继续禁用外部 provider；AI 仍是 sidecar，不决定仓位和订单。

这能约束本系统传入和接受的 evidence，**不能证明一个有网络能力的远端模型不会自行搜索，也不能删除模型参数中记住的未来事实**。因此尚未开放历史 AI 决策；未来需要隔离检索、禁用工具/网络、完整调用记录和相同 OOS 的 A/B 对照。不能把“只引用合规 evidence”宣传为模型绝对没有未来知识。

## 18 项逐项判断

| 项 | 复核结论及本版处理 |
| --- | --- |
| 1 universe | 确实存在不一致。新增共享支持规则，在排名前排除非沪深主板，执行同样使用。 |
| 2 停牌 | 确实存在行情行驱动的缺口。改 session spine，缺失与全天停牌分开，禁止虚构 OHLC。 |
| 3 下载完整性 | 确实需要加强。按 endpoint/logical request 保存不可变 revision、参数、获取时间、行数、文件哈希和状态；L/D/P 独立记录。分页子请求有参数 trace，未宣称每个子响应均有独立哈希。传输成功与源数据完备明确分开。 |
| 4 退市 | 原有上市区间过滤有用，但不能证明股票总表完整。增加独立历史 inventory receipt 门禁；真实无偏性尚未验收。 |
| 5 时间语义 | 原来的业务日期/标签不足。增加获取时间、内容绑定和精确截止校验，禁止将新下载冒充旧时点可见。 |
| 6 AI evidence | 确实存在信任边界不足。加强 ingestion、不可变引用和 provider 输出校验，历史 replay 不联网。 |
| 7 行业 | “已用当前行业回填”不成立：原代码将未知行业拒绝。保留 `max_industry` 及历史证据要求，不为了通行而关闭风控。代价是真实数据暂时可能无法正式运行；未来可另建经过对照的无行业约束 baseline。 |
| 8 Walk-Forward | 命名意见成立，不是拟合算法 bug。新增 `rolling-oos` 命令，旧命令兼容；历史窗口是预热，不训练参数。 |
| 9 成交 | 原有 T+1、涨跌停、Gap、ADV、滑点已有控制，不能说完全缺失。本版补状态门禁和真实数据开盘量/观测时间证据；无法确认时 no fill。日频撮合仍不能证明队列成交和实际流动性，不能升级为实盘级仿真。 |
| 10 费用 | 原有最低佣金、卖出印花税和按生效日期的过户费表已存在，无需重写。仍是沪深主板、配置化佣金、固定滑点模型；拆单最低费、实际券商附加费和股息税最终差额不是完整券商账单复刻。 |
| 11 复权 | 因子用复权关系、成交用原始价格已有隔离，核心指控不成立。本版额外限制停牌跨除权估值；公司行动资料完整性仍是关键。 |
| 12 cache | 元数据长期缓存风险成立。stock_basic/trade_cal 默认 24 小时 TTL，刷新形成新 revision；失败不能静默退回旧成功状态。历史行情显式刷新，未增加后台调度。 |
| 13 重叠版本 | 风险成立。唯一键冲突拒绝，完全相同记录可去重；不静默采用任意 range。旧平面缓存没有证明材料，不能自动认作可信。 |
| 14 年收益 | 语义需要修正。显示样本年度区间与年化区别；没有权威日历覆盖证明，即使有 1/1 和 12/31 端点也不宣布完整自然年。旧 JSON 字段保留兼容。 |
| 15 Win Rate | 粒度担忧成立。明确 `closed_fill_*`，旧 trade/win 字段弃用提示；未假装已经实现 position episode 统计，后续再做。 |
| 16 AI sidecar | 判断准确，是保留的 baseline 设计。AI 不改变订单，不宣称 AI Alpha。未来 mechanical 与 AI overlay 必须同源同窗比较。 |
| 17 技术指标 | 同意优先级，不增加 MACD/RSI/ML/RL。 |
| 18 性能 | 同意先正确性。分页是防截断措施，不代表已完成十年数据下载优化。 |

## 复核额外发现

1. 交易日历缺一天可能连行情缺失检查一起绕过。下载现在核验整个请求范围的每一个自然日、重复日期及开闭市标记，不用工作日推断补齐。
2. 默认 stock_basic 字段不应被假定包含退市日期；显式 fields 和分页边界必须一起处理。
3. 缺行情持仓可能错误估值；除权日旧价延用、退市持仓无结算依据均改为停止。
4. 公司行动只按区间内除权日下载，可能遗漏区间内登记、区间外除权的已公告事项。增加标准化 actions 补充输入及冲突检查；仍必须由独立档案证明完整，不能由 `actions_complete=true` 单独担保。
5. benchmark、下一交易日、公司行动和预热数据都可能泄漏；session receipt 必须一起绑定，不能只检查候选股票。
6. provider 可能修改传入的 evidence 对象；现在深拷贝并按原始对象验证输出。

## 下一版优先级

* P0：获得可审计的真实历史 inventory、ST/行业、全天/盘中停牌、公司行动及修订档案；选包含退市、长期停牌、除权和新股的短区间逐笔对账。没有这些资料就保留重建数据状态，不绕过门禁。
* P0：开盘证据扩展到当时的状态、限价和价格保管链，建立订单级回放与队列/部分成交模型。现有开盘量证据只是必要条件；日频区间、日终状态、量能代理仍不足以认证无未来依赖和真实可成交。
* P1：明确退市结算、长期停牌估值与股息税处理；补完整自然年覆盖证明及 position episode 统计。
* P1：以连续前向采集建立真正的 available_at 历史，而不是给旧行情补时间。
* P2：完成上述真实验收后，再评估下载批量化和 AI overlay 的同条件 A/B。保留 mechanical baseline。

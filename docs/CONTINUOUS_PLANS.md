# 持续交易计划工作台

双击根目录 `启动工作台.cmd`，点击左侧“持续交易计划”，或打开 <http://127.0.0.1:8765/planner>。

如果显示“网页已更新，后台仍是旧版本”，请重新双击启动入口。启动器核对后台版本，默认端口被旧版占用时会在新端口打开当前版本；无需结束旧进程。仅关闭浏览器不会结束后台。使用启动器新打开的地址，避免继续操作旧标签页。

本模块管理的是每日条件计划和用户持仓快照，不接券商，不会把计划自动变成成交。历史 PIT 回测引擎和模拟账本保持独立。

## 怎么使用

1. 填写账户总资产、可用现金和风险参数，保存。未填写资金时可以看条件价格，股数保持 0。预设参数只是可修改的研究起点，不是已了解你情况后的个人建议。
2. 在独立的“收盘账户快照确认”卡填写同日收盘后的北京时间、冻结资金和其他资产。昨日收盘确认在次日早间仍可作为账户资料，但开始新的收盘复核时仍需提交本次行情日的同日收盘快照。其他资产非零时必须填写说明；这两类资金当前没有建模，新的候选仓位仍保持 0，但风险提示会保留。确认框不会默认勾选；即使当前没有持仓，也要明确勾选“确认没有需要记录的持仓”。
3. 如有持仓，录入沪深主板代码、实际股数、成本价、买入日期。数量填 0 是更新“当前已无持仓”，不会卖出股票。成交后同步更新持仓和现金；分批买卖暂用券商汇总持仓维护，尚无逐笔实盘成交账本。账户或持仓修改后需要重新做收盘账户快照确认。
4. 交易日 16:00 后点“开始复核”。缺少当日名单时先自动检查数据源返回的主板目录，再复核候选及全部持仓；首次全目录抓取可能需要数十分钟。持仓即使掉出 Top N 也会继续检查。
5. 查看入场价格区间、计划股数、止损价、止盈价、最长持有交易日，以及已有持仓的继续观察/止损/止盈/到期/新闻待核实状态。价格出区间不沿用旧数量。拟退出数量只代表下一可交易时段的人工执行计划，仍须核对券商可卖股数。
6. 可勾选“页面打开时每 30 分钟自动复核”。这是本地网页触发的日频复核；关闭网页后不再发起新任务，已经提交的后台任务仍会运行至结束或取消。没有盘中逐笔监控、手机推送或无人值守后台调度。

每次保存复核版本、证据和变化说明。修改账户或持仓后最新计划中的旧股数立即失效；新版计划只用于独立日历的下一交易日，并在该日 16:00 到期。休市日不生成新计划；周五计划按实际下一交易日处理。历史版本供回看。盘中监控须重新确认实际账户，在原计划股数上限内重算，详见 [盘中监控](INTRADAY.md)。

账户确认只表示用户对收盘人工快照和实际持仓股数的声明。昨日收盘的确认在次日早间仍可作为账户资料；新的收盘复核必须使用本次行情日的同日快照，不能用昨日资料代替。页面用固定 1.00 元容差显示持仓市值与现金、冻结资金、其他资产的对账差额；对账未通过或确认资料已失效时，不允许把计划当作新的可执行指令。冻结资金和其他资产暂不参与新仓模型，因此即使账户快照已确认，非零项仍会暂停新仓并保留风险提示。

## 价格、数量和退出规则

- 默认入场带宽为已核验收盘价上下 1%，使用区间上限计算最坏买入成本。
- 初始止损为区间上限下方 6%；止盈为入场价加两倍止损距离；最长持有 20 个观测交易日。它们都可配置，目前是固定百分比规则，没有额外增加技术指标。
- 数量同时受可用现金、每股仓位上限、总仓位上限、单笔风险、组合剩余风险和成交额容量限制，并向下取 100 股整手。多只候选共享同一份剩余预算，不能各自重复使用全部现金。
- 研究预设：单笔风险 0.5%，单股资产占比最多 10%，总持仓最多 60%，组合压力风险最多 2%。已有持仓的压力风险也占用预算。
- 风险测算包含卖出价格比止损再差 1% 的缓冲及简化费用：佣金万三、单边最低 5 元、过户费十万分之一、卖出印花税万五。它不是券商真实费用结算，1% 缓冲也不是最大损失保证。
- 持仓以收盘价格判断止盈止损；触发后计划退出全部记录股数。没有乐观假设盘中触价即成交。T+1、停牌、涨跌停和跳空均可能导致不能及时退出。
- 原始价用于价格和风险计算；前复权仅检查趋势/持仓期间除权基准。复权日期缺失或比例发生变化时，先要求核对券商成本与退出价，不自动调整股数或派息。
- 持仓成本和日期未变时，每次刷新不移动原止损、止盈和最长持有期；修改全局参数也不偷偷放宽已有持仓的止损。当前未实现移动止盈、分批止盈或订单执行。

## 四类因素如何参与

新增“国内外事件参考”和“财报参考”独立展示，不并入下表权重、不改变原机械排序和股数。来源、日精度公告、累计指标与研究实验的边界见 [国内外事件与财报说明](NEWS_AND_FINANCIAL_CONTEXT.md)。

| 因素 | 默认展示权重 | 当前来源和实际作用 |
| --- | ---: | --- |
| 机械趋势 | 70% | 原有 60/120 日动量排名；继续决定候选及预算分配顺序 |
| 市场状态 | 20% | 基准指数相对 MA120 的趋势开关；弱势时暂停新开仓；不是全市场情绪指数 |
| 新闻 | 10% | 东方财富新闻聚合的近 7 日标题/摘要，透明词典评分；立案调查、财务造假等重要词单独要求人工核实 |
| 社区 | 0% | 东方财富股吧近期公开讨论样本；默认仅观察，可设置权重但最多 5%，至少 10 条有效样本才显示情绪值 |

**权重是未经过样本外校准的研究预设，只影响综合展示分数，不改变机械排名或仓位数量。** 市场趋势和重大新闻词是独立风险条件。普通下跌/减持词不会自动当成重大事件；社区情绪不直接触发买卖，也不覆盖止损。

缺失因素显示未知，并输出综合分数下限/上限，不能填成中性或把剩余权重偷偷放大。新闻词不证明事件属实，社区不是公司事实；搜索样本也不是完整新闻或投资者意见总体。当前使用词典，不是 LLM 的语义研究/辟谣。后续应积累前瞻数据，对同一 OOS 比较机械基线与新闻/社区增强版本，再决定是否给它们交易决策权重。

## 时间与存储架构

```text
网页 /planner
  → 受限本地 API（CSRF、同源、单任务）
  → planner-review 独立子进程
  → 当日筛选 + 全部持仓行情 + 新闻/社区采集
  → 实际采集后冻结 cutoff → 数据核验 → 风险计算
  → 不可变计划版本 + 网页变化提示
```

- `planner.py`：手工账户/持仓、条件价格、共享风险预算、持仓复核、版本发布。
- `context_feed.py`：固定来源的只读采集；HTML 清洗、股票映射、时间校验、证据指纹。不会执行网页脚本或社区内容。
- `runtime/planner/plans.sqlite`：账户参数、持仓快照及审计、证据、复核版本。独立于模拟交易 ledger。
- `runtime/current-cache/`：原始响应、真实采集时间、请求和哈希；不修改全局代理。
- `runtime/web-runs/<id>/planner-result.json`、`receipts.json`：复核详情和来源记录；自动选股子结果位于 `screen/`。取消/失败的任务结果不进入网页最新已发布计划。

证据有 `evidence_id / url / published_at / available_at / fetched_at / content_hash`。发布时间取自采集接口的来源字段；社区使用原帖发布时间，不使用最后回复时间。无法解析、晚于实际采集时间或无法映射股票的材料拒绝；`available_at` 为实际获取时间。标题词典标签可随规则版本重新计算，证据原文和时间不会因此重写。

今天下载的旧新闻不能用于过去的决策。这里的聚合来源时间只支持当前前瞻研究，并未证明历史内容未编辑，不能送进严格历史 PIT 回放当作可信历史证据。手工填写时间标记为未核实、只供展示。LLM 未来也只能引用 ingestion 已冻结、截止时点前可见的证据，不能自报发布时间；本模块尚未接通 LLM 新闻决策。

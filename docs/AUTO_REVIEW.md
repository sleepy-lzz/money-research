# 自动复盘与持续观察

这份说明定义 `daily-lab` 的用户用法和验收边界。它用于把每日真实收盘后的选股、证据和随后价格观察保存成可复核的实验记录，不连接券商，也不替代人工执行。

## 运行方式

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m ashare_agent daily-lab
```

每日运行会完成软件检查、真实收盘候选和新闻采集，并写入当日独立运行目录。电脑和 Codex 需要在运行时保持开启；这是一项本地工作日任务，会使用相应的模型和软件额度，不是 24/7 云服务。

本任务的自动安排是北京时间工作日 **16:30**，在当前 Codex 对话中继续运行本地命令并复盘。它不依赖网页保持打开，但电脑必须开启、Codex 必须运行，不能把它视为设备关机时仍然运行的云服务。

新增独立模拟账户后，软件检查包含其预检、幂等与报告恢复测试。当前任务尚未绑定实际模拟账户与可信 Snapshot，仍执行价格观察，不会自动创建虚拟金额或改写手工持仓。真实模拟每日推进需先通过 [模拟账户数据验收](PAPER_ACCOUNTS.md)。

双击 `查看自动复盘.cmd` 可以直接打开最新报告。该入口只读取 `runtime/daily-lab/latest.html`，不依赖旧的 web 后台重启流程。

## 每日冻结与观察口径

每日收盘后，程序将当天第一次有效运行的候选、新闻和输入指纹冻结为当日观察基准。后续重复运行不得用新结果回填旧的 signal。每日行情变化进入 `input_hash`；选股参数、股票范围规则、新闻处理源码、实验实现、日历版本等进入可读 `rules_manifest/rules_hash`。跨日按同一规则身份比较；同一天规则改变也不能覆盖已有冻结，后续新日期再建立新规则样本。旧记录缺失 manifest 时保留 legacy 状态，不补造版本证据。

每个冻结日记录四组固定对照：

1. 机械规则 Top 5；
2. 60 日动量 Top 5；
3. 120 日动量 Top 5；
4. `news_guard`：机械 Top 20 子集内经过新闻守门的结果。

价格观察使用统一口径：以 D+1 交易日开盘作为观察起点，分别记录 D+1、D+5、D+20 交易日对应收盘的结果。交易日由冻结的独立日历定义，不能从供应商返回的基准行数推算；当前日历依据沪深交易所2025/2026年度休市公告，原HTML、实际获取时间和SHA-256已归档。缺基准行不会顺延到期日。每个观察窗口独立判断；超日历覆盖范围记为 `calendar_unknown`，不妨碍已覆盖的短窗口。

停牌、缺失行情、公司行为或除权导致价格不可比时，结果记为 `unknown`；不删除分母、不补填旧信号，也不把未知当作亏损或收益。日历的今天归档不证明历史当时已持有；来源获取时间晚于冻结时间时拒绝新增冻结。

新闻采集只记录当时可见的材料和来源时间。来源缺失、发布时间无法核验或社区材料不足，都必须明确显示为缺失或未知。缺失不等于中性。

## 结果不代表什么

`daily-lab` 的结果是收盘候选和事后价格观察，不是以下任何一种结果：

- 券商成交回报或真实 fills；
- 现金账户收益、净值曲线或可提现利润；
- 带历史时点证据的完整回测；
- Alpha、统计显著性或未来收益保证。

观察价差不包含真实委托排队、成交失败、滑点、费用、现金占用和持仓组合影响。几天的涨跌不能确认收益；固定持有观察期也不是交易建议。

样本尚未达到 60 个已冻结交易日时，优先评估数据与软件可靠性；60 日只是初步研究的观察门槛，不是收益、Alpha 或统计结论的通过线。不同观察窗口会重叠，样本存在相关性，不能据此制造虚假的统计显著性或夸大有效性。

当前因子实验候选只允许使用机械 Top 20 子集，不能据此宣称发现了全市场新增 Alpha 因子。

## 每周 AI 复盘

日常采集之外，当前主代理持续处理 [项目完成计划](PROJECT_COMPLETION_PLAN.md) 中有明确验收条件的待办。每周五，以及待办处理完、发现重大缺陷或准备关键策略/风险变更时，使用 `gpt-6-astra / xhigh` 子代理独立审查整个项目。先独立判断，再参考官方资料、GitHub、论坛和公开社交平台（雪球、股吧、Reddit 等）的可核验经验。主代理复核证据和适用范围，选择值得做的修复、实现并测试；审查意见不等于修改指令。

社交内容可以启发研究假设，帖子热度、截图收益和转发次数本身不能证明策略有效。采样偏差、删帖、机器人、推广内容、修改时间与原发布时间差异必须纳入判断。研发参考文献不自动成为历史决策输入；进入信号或回放的材料必须走 ingestion 的不可变时间与内容登记。LLM 只能引用已登记证据，不能自行补写可见时间。

自动化不会每次都强行新增功能。软件里程碑达标后转为维护和真实前瞻观察；仅在有新问题、可验证改进或样本成熟时继续动作。关键决策模型不可用时记录待复核，其他独立的采集、测试和明确软件修复可继续。

每周五的 AI 复盘写入：

```text
runtime/daily-lab/reviews/
```

复盘可以总结覆盖率、未知项、四组固定对照的观察差异和需要继续检查的问题。因子或参数建议先写成有预先规则、适用范围和失败条件的独立实验，同时保留固定 baseline；不能每天追涨或用同一批数据选参数再宣称样本外有效。默认策略的晋升需要新的证据、独立关键复核和可审阅的变更记录，不由日报程序按短期涨跌直接改写。

关键变更的复核使用 `gpt-6-astra`、`xhigh` 推理强度已获得用户授权；普通工作默认使用常规模型。模型建议是研究意见，不能改变每日冻结事实，也不能绕过未知数据门槛。

## 文件与复现

新增 `runtime/daily-lab/latest-run.json` 与每次目录的 `run-state.json`，用于判断 starting、software_checks、benchmark、observation、selection、context 及结束状态。`latest.json` 是报告视图，不能单靠它判断进程是否仍在运行。下一次拿到独占锁却发现旧状态为 running 时，会在新日志中记录前次未正常结束，不改写旧冻结事实。没有启动的日期不会产生运行日志，必须作为漏运行单独记入审计。

最新汇总文件为：

```text
runtime/daily-lab/latest.html
runtime/daily-lab/latest.json
```

每次运行应保留独立目录，并至少包含：

```text
report.html
report.md
result.json
checks.log
```

`result.json` 保存状态、冻结日、四组对照、观察窗口、未知原因、来源指纹和版本信息；`checks.log` 保存软件检查输出，来源请求记录在 `receipts.json` 和 `screen/result.json`。报告路径更新时，旧的独立目录仍可读，不能只保留一个会被覆盖的结果文件。

`observations.json` 保存完整观察结果及未知原因；汇总中最多展示 50 条未知事项并保留总数。冻结时的新闻覆盖与最新价格评价状态分别记录，不能把“没有发现风险词”视为新闻覆盖完整。

## 验收边界

一次可审阅的运行至少应能回答：

1. 软件检查是否通过，检查日志是否保留；
2. 当天第一次冻结的日期、输入和 `source_hash` 是什么；
3. 四组固定对照各自的候选和状态是什么；
4. D+1、D+5、D+20 的价格观察是否可用，哪些项目是 `unknown` 以及原因；
5. 是否保留了当次独立目录和最新 HTML/JSON 汇总；
6. 是否保留固定 baseline，新实验有预先规则，改进有取舍理由、实现和验证记录。

旧候选的后续观察先于当日新增选股，二者分别记录 `phases.observation` 和 `phases.selection`。目录、选股或新闻源失败不应阻断本来可完成的旧样本观察；观察失败也不应伪装成新候选冻结成功。部分完成必须保留成功部分及失败原因。

以下情况应判为继续观察或未完成验收，而不是成功：真实数据覆盖不足、新闻来源不可核验、关键价格未知、冻结日被后续结果覆盖、不同 `source_hash` 混批，或报告把观察结果写成成交/账户收益。

个人 planner 的手工持仓、资金参数和持仓动作不写入 `daily-lab`，两条记录链路保持独立。daily-lab 也不自动下单、不自动改写 planner profile，不因一次运行或几天价格变化晋升主策略。

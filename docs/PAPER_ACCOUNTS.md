# 独立模拟账户

网页工作台导航“模拟账户”，地址 `/paper`。此账户使用单独虚拟资金，不导入或改写持续交易计划中的手工持仓，不连接券商。现在可以建立账户并检查数据；只有符合严格前瞻契约的 Snapshot 才能推进。

## 日常操作

1. 填名称和自己选择的初始虚拟金额，创建零持仓账户。创建时没有交易日、委托、成交或策略收益。
2. 从 `runtime/snapshots/` 选择已构建的数据版本。“出现在列表中”不代表可信；点击“检查是否可运行”查看完整原因。
3. 交易日北京时间 16:00 后，预检通过才可“推进今日模拟”。每日只推进今天；D 日冻结次日意图，D+1 才尝试成交。同日重试不重复成交。
4. 查看账户持仓、条件委托、已成交、费用以及最近处理日。页面任务“已完成”只表示检查程序完成，数据可能仍为 waiting_data；两种状态分别显示。

合成演示不允许进入此账户。腾讯/新浪的当前研究日线也不能替代严格 Snapshot 的退市全集、交易状态、限价、公司行为与实际可见时间证据。缺少开盘成交量/时间证据时，引擎拒绝相应委托，不能把日线全日成交量当开盘容量。费用与滑点仍是配置中的保守模拟假设，不能声称重建真实排队成交。

## 状态及恢复

| 状态 | 意义及处理 |
| --- | --- |
| waiting_data | 尚未通过数据/时点检查；读取具体原因。无交易日时收益为未知 |
| ready | 临时账本完整预检成功，正式账户尚未推进；实际推进会再次检查 |
| advanced | 本日 session 和完整结果已在同一 SQLite 事务内提交 |
| already_processed | 读取本日已保存结果，没有新增订单或成交 |
| report_failed | session 已提交，外部报告未完整保存；重试恢复已提交结果，不重新成交 |
| missed_session | 已错过必须处理的交易日；旧账户终止继续推进，保留原记录并建立新的对照账户，不回填前瞻 |
| version_blocked | 代码、配置或账本归属变化；保留只读，核查并建立新版本账户 |

每个账户单独保存在 `runtime/paper-accounts/<id>/`：创建时固定 `account.json`，首次有效推进后才出现 `account.sqlite`；每次推进尝试有 `attempt-*.json`；每日完整报告保存为 `run-YYYY-MM-DD.json`，并保留 `latest-run.json`。后续交易日前先恢复尚未落盘的上一日报告，避免覆盖唯一结果。外部报告冲突不静默覆盖。

账户的收益与估值截至“最近处理日”，不代表盘中实时净值。尚未处理 session 时可用资金只是虚拟起始资金，收益为 null，不能拿空账户的平线证明策略有效。

## 命令行

在项目目录使用 `.venv\Scripts\python.exe -m ashare_agent` 后接：

```text
paper-account create --name "机械基线观察" --initial-cash 100000
paper-account list
paper-account state --id <账户ID>
paper-account check --id <账户ID> --snapshot-id <快照目录名>
paper-account advance --id <账户ID> --snapshot-id <快照目录名>
```

示例 100000 是用户自选虚拟金额，不是实际资金。此命令不接受 `--replay` 或临时 `--config` 覆盖。已有 `paper/daily/backtest` 命令不能写独立模拟账户目录或拥有相应身份标记的账本。
